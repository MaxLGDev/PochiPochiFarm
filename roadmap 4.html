Pochi-Pochi Farm — Build Roadmap

Check items off as you go. Restructured to reflect the actual systems built so far — the Laboratory (per-crop research/automation) replaced the old generic Shop-based crop-permission and automation phases. Work top to bottom, phase by phase — don't skip ahead.

Phase 0 — Project Setup

Phase 1 — Crop Data (ScriptableObjects)

Phase 2 — Grid Foundation

Phase 3 — Tile Unlocking

Phase 4 — Zones

Fixed hardcoded rectangular regions layered on top of normal tile unlocking. Implemented as chapter-gated rather than per-zone-Objective-gated: a zone unlocks on completion of its associated Journal chapter, with no separate per-zone unlock button. Tile stays fully unaware of zones — GridManager owns zone logic. Nothing (no tile interaction/unlocking) is possible inside a locked zone.

Phase 5 — Coins, Water & Crop Resources

Harvesting no longer awards coins directly — it increments a per-crop-type count. Coins come only from explicitly selling. ResourceManager owns coins, per-crop-type counts, and multi-resource costs via CostEntry.

Phase 6 — UI Feedback Helpers

Small, reusable, single-purpose animation components — not a big UI manager — so they can be dropped onto any button/element.

Phase 7 — Crop Growth Cycle (Manual)

Phase 8 — Crop Growth Visuals

Implemented via discrete seed-growth-stage sprites (swapped as the timer crosses thresholds) instead of a progress bar/slider or continuous sprite scaling.

Phase 9 — Laboratory (Research & Automation)

Replaces the old generic "Shop Upgrades: Crop Permissions" and "Shop Upgrades: Automation" phases. Per-crop research and automation live in a dedicated Laboratory system with their own manager and UI, gated by multi-resource CostEntry costs (coins and/or crops) instead of flat coin costs.

Phase 10 — Upgrades UI

General Upgrades panel for global upgrades (multipliers, click power, water tank) — separate from the Laboratory, which only handles per-crop research/automation.

Data + logic layer fully built (UpgradeData SO with PreviousUpgrade prerequisite chain, UpgradeState enum, UpgradeManager with GetUpgradeState/AreRequirementsMet/UnlockUpgrade, OnUpgradeUnlocked event) and UI scripts written (UpgradeNodeUI, UpgradesUI, ConnectorUI w/ midpoint-distance-Atan2 line math). Node placement, category group labels, and connectors are now in — the scrolling UV animation on ConnectorLine remains abandoned (Unity masking overrides runtime materials). A tooltip was considered and dropped in favour of plain text under each node (effect + cost) — simpler and enough.

Phase 11 — Upgrades: Income & Click Power

Revised scope: the +20%/+30% income multiplier upgrades were never built and are not planned — replaced by the max coin storage cap upgrade below. Max coins starts at 20 and AddCoins clamps to it, so any coin price above the current cap is unreachable until enough max-coin upgrades exist — the game can't be completed until the chain below is in.

Phase 12 — Upgrades: Water Tank

Max water capacity, water efficiency (skip-water chance), and water regen power/speed upgrades all complete — WaterManager subscribes to OnUpgradeUnlocked and self-applies each effect. All nodes placed and tested.

Phase 13 — Objectives / Farm God Journal

All objectives and chapter-progression logic are implemented, and every chapter is now filled in: Chapter 1 has 5 tutorial objectives, Chapters 2 and 3 have 10 each, and Chapter 4 has 4 cumulative-only objectives (full list in claude/journal-objectives.md). Targets are first-pass values, to be tuned during the full playthrough test (Phase 14). Chapter 1 also serves as the tutorial (Phase 19), so its objectives are ordered to teach the basics: click Dirt, earn coins, buy water, unlock Radish, unlock Carrot.

Phase 14 — Win Condition

Win condition is clearing Chapter 4; the check is fired from the Journal system on chapter completion.

Phase 15 — Settings Menu

Kept intentionally simple — a single settings panel, no extra polish beyond what's listed.

Phase 16 — Save System

Simple JSON file save/load via Unity's JsonUtility + File I/O to Application.persistentDataPath — no third-party plugin needed. Each manager owns and serializes only its own slice of state (same single-ownership principle as everything else); a dedicated SaveManager orchestrates. ScriptableObject config (CropData, ZoneData, UpgradeData) is never serialized itself — only referenced by name/ID and re-resolved against the existing asset lists on load.

Phase 17 — Juice & Small Effects

Small, single-purpose visual feedback layered onto existing systems — not new mechanics. Reuse PunchAnim/WiggleAnim/FadeAnim from Phase 6 where they fit. Floating text is done; adding PunchAnim/WiggleAnim to it was tried and dropped (coroutine errors on freshly instantiated objects, purely cosmetic).

Phase 18 — Sound Design

SoundManager plus SFX for every player-facing action across all systems.

Phase 19 — Tutorial (Chapter 1)

Chapter 1 doubles as the tutorial: a short, simple guided sequence (a few minutes) that darkens the screen except for the element the player should click, with a line of text saying what to do. The tutorial is finished once Chapter 1 is claimed. Kept deliberately easy — no skip system, no branching, no extra mechanics. Placed before Polish & Cleanup so the final playtest and build include it. Tutorial progress is derived from existing state (JournalManager.IsChapter1Claimed / chapter 1 objective progress) rather than stored separately, so no new save data.
